# QuietNote Daily Plan — 2026-03-25

## A. Today's Objective

Replace the current fine-tuned Gemma 2B model with a higher-quality base model — the model is now the single biggest blocker to a usable product experience.

## B. Why This Matters

After the 03-24 fixes (KV cache reset, max_tokens reduction, guardrail logging), multi-turn conversations no longer degenerate into gibberish. But today's live testing reveals that the **core model quality is still unacceptable**: every response fixates on "embarrassment" regardless of topic, produces made-up words ("inconceving", "negaitve", "gratiously"), gives unsolicited advice (meditation exercises), and never asks reflective questions despite the system prompt explicitly requiring them. On turn 3, when the user shared a *positive* experience about finishing a project, the model responded with the exact same embarrassment/boundary lecture from turn 2. The model is not following the system prompt at all — it's generating from its fine-tuned distribution regardless of input. No amount of parameter tuning, guardrails, or prompt engineering can fix a model that doesn't follow instructions. Switching to a model that actually responds to the system prompt is the highest-leverage change possible.

## C. Top 3 Priorities for Today

1. **Evaluate and switch to a stock Gemma 2 2B-IT or TinyLlama 1.1B-Chat model via WebLLM** — The current `quietnote-gemma-2b-q4f32_1-MLC` is a custom fine-tune that has clearly overfit on a narrow "embarrassment/boundary" distribution. Stock instruction-tuned models from WebLLM's model zoo should follow the system prompt much more reliably, even if they lack domain specialization.

2. **Fix the MoodTracker close button (X) not dismissing the modal** — During testing, clicking the X button and backdrop both failed to close the mood tracker. The modal wrapper div (`fixed inset-0 z-50`) covers the backdrop, preventing backdrop clicks. The X button handler fires but the modal stays open — this may be an AnimatePresence exit animation issue or a state propagation bug. This is a visible UI bug that makes the mood tracker feel broken.

3. **Add click-outside-to-close to the modal wrapper and verify mood save works** — The "Save Mood" button was clicked but the mood count stayed at 0. Either the save handler has a bug or the emotion selection wasn't registered. The modal also needs `onClick` on the wrapper div (with `stopPropagation` on the inner content) to allow dismissal by clicking outside.

## D. Concrete Implementation Plan

**Root cause:** The custom `quietnote-gemma-2b-q4f32_1-MLC` model was fine-tuned on a narrow dataset that causes it to fixate on "embarrassment" content regardless of user input. It does not follow the system prompt's instructions about asking questions, keeping responses concise, or avoiding advice.

**Exact changes:**

- In `src/hooks/useMLCEngine.ts`:
  - Change `MODEL_REF` to use a stock WebLLM model. Candidates (in order of preference):
    1. `gemma-2-2b-it-q4f32_1-MLC` — Gemma 2 2B instruction-tuned, likely best instruction following
    2. `Llama-3.2-1B-Instruct-q4f16_1-MLC` — Llama 3.2 1B, very capable for size
    3. `TinyLlama-1.1B-Chat-v1.0-q4f16_1-MLC` — TinyLlama chat, smallest option
  - Update the WASM library path if needed
  - Update context window size if different from 2048

- In `src/App.tsx`:
  - Update any model-specific references (the `MODEL_REF` import should handle it)
  - May need to adjust `temperature` (0.4→0.6) and `maxTokens` (150→200) for the new model's behavior
  - System prompt may need minor adjustment for the new model's chat template

**Where it lives:** `src/hooks/useMLCEngine.ts`, `src/App.tsx`

**Dependencies:** WebLLM model zoo must have the target model available. Check `@mlc-ai/web-llm` package for available models.

## F. UX & Design Review

### How the app feels as a product:
The app looks polished. The layout is clean, the loading indicator works, sessions save, and the AI disclaimer adds trust. But the moment you start chatting, the experience collapses. The model's responses are so divorced from what the user says that it feels like talking to a broken chatbot. A journaling companion that lectures you about embarrassment when you share a celebration is worse than no companion at all — it actively undermines the sense of being heard.

### What a first-time user would think:
1. "Nice loading screen, a bit long but I see progress"
2. "OK the response is long and doesn't really address what I said... and what does 'inconceving' mean?"
3. "It's lecturing me about embarrassment again? I was talking about saying no..."
4. "I just shared something GOOD and it's still talking about embarrassment? I'm done."

### Biggest UX gap right now:
**Model quality is THE gap.** The 03-24 fixes successfully prevented degeneration/gibberish and capped length somewhat. But the fundamental issue is that the fine-tuned model doesn't follow the system prompt and generates from a narrow overfit distribution. Everything else in the product (UI, sessions, mood tracking, privacy) is secondary to getting the core conversation to feel responsive and human.

### Secondary UX gap:
The mood tracker modal can't be closed, which makes the feature feel broken even if the tracking logic works. This is a quick win.
