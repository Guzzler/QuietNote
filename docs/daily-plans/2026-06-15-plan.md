## A. Today's objective

Make logging a mood **contextual and unambiguous** by adding a gentle **"How are you feeling?"** chip row at the moment a user starts a fresh free-write entry — one tap logs a mood automatically (which feeds the existing mood-aware prompts) and offers an "add detail" path into the full tracker. Resolve the ambiguity of the header Heart button **without orphaning** Mood History/Insights. Fundamental Problem 4 ("feels like a tech demo, not a journal"), roadmap item A4.

## B. Why this matters

Today the only persistent mood entry point is a **Heart icon in the header** ([`App.tsx:774–783`](../../src/App.tsx)) labeled "Mood". It is *ambiguous*: a first-time user can't tell whether it logs a feeling, opens a chart, or is decorative — and it sits far from the act of writing, so almost nobody uses it at the natural moment (the start of an entry). A1 already proved the principle that "the right affordance at the right moment" beats "a button in the chrome" ("just start writing" drove 36% of real entries). A4 applies the same move to mood: a soft, optional **"How are you feeling?"** row right where you begin writing turns mood capture into a one-tap, in-context gesture. The captured mood immediately enriches the AI's context (`buildSessionContext` already surfaces recent emotions and mood trend into the system prompt), making responses feel more attuned from the first reply — the core "write → feel heard" loop. Crucially, this is **additive and reversible**: keyword extraction (`emotionExtractor`) stays as the fallback for entries where no chip is tapped, and the full tracker (intensity/contexts/note + History + Insights) stays fully reachable.

## C. Current-state assessment

**Mood data model** — [`src/types.ts:40–70`](../../src/types.ts): `MoodEmotion` is a 10-value union (`happy, sad, anxious, angry, calm, excited, frustrated, content, lonely, grateful`). `MoodEntry = { id, sessionId?, emotion, intensity (1–10), contexts: MoodContext[], note?, ts }`. **`sessionId` and `note` are optional and `contexts` may be empty** — so a lightweight quick-capture entry (emotion + neutral intensity, no contexts/note) is a valid `MoodEntry`. This is the key fact that makes one-tap logging clean.
