# QuietNote Daily Plan — 2026-03-23

## A. Today's Objective

Implement response guardrail blocking mode for critical medical/diagnostic patterns and harden the system prompt with explicit medical refusal instructions — the two highest-impact safety items carried forward from 2026-03-22.

## B. Why This Matters

The response guardrails currently operate in monitoring-only mode: when the model generates medical advice or diagnostic language, the system logs a console warning but **shows the harmful response to the user unchanged**. For a mental health app targeting potentially vulnerable users, this is the most urgent safety gap. The system prompt also lacks explicit medical refusal examples, and small quantized models follow in-context examples far more reliably than abstract rules. Together, these two changes create defense-in-depth: reduce harmful generation at the prompt level, and catch anything that slips through at the output level.

## C. Top 3 Priorities for Today

1. **Implement blocking mode in `responseGuardrails.ts` for medical/diagnostic patterns** — Add severity tiers (BLOCK/WARN/MONITOR) so that responses containing medication recommendations, dosage information, or diagnostic claims are replaced with a safe fallback before reaching the user.

2. **Harden system prompt with medical refusal few-shot example and explicit instructions** — Add a concrete medical refusal demonstration to SYSTEM_INSTRUCTION so the model has an in-context example of correct boundary behavior, plus explicit "NEVER recommend medications/supplements/treatments" language.

3. **Add 8 medical-edge-case eval cases targeting supplement, dosage, and indirect diagnosis patterns** — Expand the eval suite beyond the existing 32 cases with prompts that specifically test the medical refusal boundary (supplement advice, dosage questions, natural remedy traps, indirect diagnosis).

## D. Concrete Implementation Plan

### Priority 1: Response Guardrails Blocking Mode

**Exact changes to `src/utils/responseGuardrails.ts`:**
- Add `GuardrailSeverity` type: `"block" | "warn" | "monitor"`
- Add `isBlocked` field to `GuardrailResult` interface
- Add `BLOCKED_RESPONSE_FALLBACK` constant:
  ```
  "I appreciate you sharing that with me. That sounds like something worth exploring with a healthcare professional who can give you personalized guidance. In the meantime, how are you feeling about it?"
  ```
- Assign severity to pattern categories:
  - `MEDICAL_ADVICE_PATTERNS` → `"block"` (medication names, dosage, "you should take", "I recommend")
  - `DIAGNOSTIC_PATTERNS` → `"block"` ("you have depression", "sounds like you have", diagnostic claims)
  - `DISMISSIVE_PATTERNS` → `"warn"` (toxic positivity, dismissal — harmful but not dangerous)
  - Length violations → `"monitor"` (quality issue, not safety issue)
- Modify `sanitizeResponse()`: when any `"block"`-severity pattern matches, set `isBlocked: true` and replace `text` with `BLOCKED_RESPONSE_FALLBACK`
- Export `BLOCKED_RESPONSE_FALLBACK` for testing

**Where it lives:** `src/utils/responseGuardrails.ts`

**Dependencies:** Verify where `sanitizeResponse()` is called (likely `src/App.tsx` chat handler) to confirm blocked responses render correctly — the `text` field replacement means no caller changes needed.

**How to test:**
- Unit test: `"I recommend taking 5mg of melatonin"` → `isBlocked: true`, text is fallback
- Unit test: `"That sounds really difficult. What's been weighing on you?"` → `isBlocked: false`, original text preserved
- Unit test: `"Just cheer up, it's not that bad"` → `isBlocked: false`, has warn-level warning
- Unit test: `"You have generalized anxiety disorder"` → `isBlocked: true`
- False-positive check: `"Your doctor can help with that"` → `isBlocked: false` (contains "doctor" but not in diagnostic pattern)

**What could go wrong:** Over-aggressive blocking on safe responses. Mitigation: only BLOCK patterns that are unambiguously harmful (specific drug names, dosage numbers, diagnostic claims). Keep WARN for ambiguous patterns. The existing pattern set is already well-scoped — the change is in response action, not pattern breadth.

### Current safety posture:
- **Eval suite:** 32 cases (27 standard + 5 red-team), 6 dimensions, scored at 3.68/5.0 weighted
- **Response guardrails:** 41 patterns across 4 categories — **monitoring-only (no blocking)**
- **Crisis detection:** 45+ phrases, 4 severity tiers — **active and blocking**
- **System prompt:** Basic empathy/boundary instructions — **no medical refusal examples**

### Safety gaps (prioritized):
1. **CRITICAL: Guardrails don't block anything.** A response saying "take 5mg of Xanax" reaches the user with only a console warning. This is the #1 safety gap.
2. **HIGH: No medical refusal demonstration in system prompt.** Small models follow examples better than rules. The prompt has a journaling example but no medical refusal example.
3. **MEDIUM: No supplement/natural remedy patterns.** The medical advice patterns catch prescription drugs but not "try melatonin" or "St. John's Wort is effective."

### Biggest model safety risk:
**Unblocked medical advice reaching users.** Priority 1 directly eliminates this by replacing harmful responses with a safe fallback.

### Mitigation (today):
- Priority 1: Catch harmful responses at output (guardrail blocking) — **eliminates the risk**
- Priority 2: Reduce harmful generation at the source (prompt hardening) — **reduces frequency**
- Priority 3: Expand eval coverage for medical edge cases — **improves detection**
