## A. Today's objective

Make the Sessions list read like a **journal index, not a row of opaque
timestamps** — each entry shows a short first-line preview, a relative
"when" ("2h ago", "Yesterday"), and a small mood dot — so users can recognize
and return to a past entry at a glance. (Roadmap **A5**, Fundamental Problem #4
"feels like a tech demo".)

## B. Why this matters

The Sessions sidebar is the only way back into a past entry, but today every row
is `Title` + a raw `new Date(updatedAt).toLocaleString()` ("6/14/2026,
9:13:42 PM"). A preview only appears when an AI **reflection** has been
generated — most entries show nothing but a title and a machine timestamp. A
real journal index lets you skim *what an entry was about* and *roughly when*.
This is the same "right cue at the right moment" principle A1 (writing) and A4
(mood) already applied — now applied to *finding your way back*. Low-risk,
fully screenshot-verifiable, and the last committed UI item before the Track C
harness work.

## E. Concrete implementation plan

### Priority 1 — Pure utils (test-first, zero UI risk)

**1a. New `src/utils/relativeTime.ts`**
```ts
// formatRelative(ts, now = Date.now()) — journal-friendly "when"
//   < 60s            -> "Just now"
//   < 60m            -> "{n}m ago"
//   < 24h            -> "{n}h ago"
//   yesterday (cal.) -> "Yesterday"
//   < 7 days         -> "{n}d ago"
//   same cal. year   -> "Mmm D"   (e.g. "Jun 14")  via toLocaleDateString
//   else             -> "Mmm D, YYYY"
export function formatRelative(ts: number, now: number = Date.now()): string
```
- Use **calendar-day** boundaries for "Yesterday" (compare local date parts),
  not a raw 24h subtraction, so 11pm→1am next day reads "Yesterday".
- Pure, deterministic given `now`. No `Intl` formatting in the < 7d branch
  (keep those string-built so tests are locale-stable); the absolute branch may
  use `toLocaleDateString(undefined, { month: "short", day: "numeric" })`.

**1b. New `src/utils/emotionMeta.ts`**
```ts
import type { MoodEmotion } from "../types";
// Solid dot colors (Tailwind bg-*-400/500 class strings), keyed by emotion.
export const EMOTION_DOT: Record<MoodEmotion, string> = {
  happy: "bg-yellow-400", sad: "bg-blue-400", anxious: "bg-purple-400",
  angry: "bg-red-400", calm: "bg-teal-400", excited: "bg-orange-400",
  frustrated: "bg-amber-400", content: "bg-pink-400", lonely: "bg-slate-400",
  grateful: "bg-green-400",
};
export const EMOTION_LABEL: Record<MoodEmotion, string> = { /* "Happy", ... */ };
```
- Mirror the 10 emotions in [types.ts:40](../../src/types.ts#L40). Keep the
  existing soft `bg-*-100 text-*-700` chips in MoodHistoryPanel **as-is**; the
  dot variant is a separate, solid swatch. (Optional, low-priority DRY: have
  MoodHistoryPanel import `EMOTION_LABEL` — only if trivially clean. Do NOT
  refactor its `EMOTION_COLORS` chip map this session; out of scope.)

**1c. New `src/utils/sessionPreview.ts`** (pure helpers used by the panel)
```ts
import type { Session, MoodEntry, MoodEmotion } from "../types";
// First user message, collapsed whitespace, "" if none.
export function firstUserMessage(s: Session): string
// The mood that best represents a session, or null.
//   1) prefer moods with mood.sessionId === s.id (most recent by ts)
//   2) else the mood whose ts ∈ [s.createdAt, s.updatedAt] (most recent)
//   3) else null  — do NOT guess from unrelated moods
export function pickSessionMood(s: Session, moods: MoodEntry[]): MoodEmotion | null
```
- Build the `sessionId -> mood` and time-window lookups **once** in the panel
  via `useMemo`, not per-row, to stay O(sessions + moods). `pickSessionMood`
  itself stays pure for testing; the panel may pre-index and call a thin wrapper
  — executor's choice, but keep the map construction memoized.
