# QuietNote Daily Plan — 2026-03-28

## A. Today's Objective

Make the loading experience feel human and helpful instead of showing raw technical logs — the loading screen is now the biggest gap between "developer prototype" and "product someone would trust."

## B. Why This Matters

Every user's first experience with QuietNote is waiting for a 1+ GB model to download. Right now they see `Fetching param cache/model/0082.bin...100%` scrolling by — language that means nothing to them. A mental health app needs to feel calm, reassuring, and trustworthy from the very first second. The loading screen is the front door; if it looks like a terminal, users will close the tab before they ever journal.

## C. Top 3 Priorities for Today

1. **Humanize the loading screen with friendly progress messages** — Replace raw WebLLM log output with contextual, user-friendly messages ("Setting up your private AI...", "Downloading model weights...", "Almost ready...") mapped to progress ranges. Keep the percentage bar but make the surrounding text warm and reassuring.

2. **Add a first-time welcome/onboarding hint** — When a user lands on the empty chat with no sessions, show a brief welcome message explaining what QuietNote does, that everything is private, and suggest trying a journal prompt or just typing. This replaces the bare "Write your journal entry to start." placeholder.

3. **Add CSS transition animations to modal open/close** — All four modals (MoodTracker, PromptSelector, PrivacyDashboard, CrisisResources) lost their entry/exit animations when AnimatePresence was removed (03-25 through 03-27). Add simple CSS opacity+scale transitions so modals don't pop in/out abruptly. This is the "re-add modal animations" item from the 03-27 plan's unresolved list.

## D. Concrete Implementation Plan

### Priority 1: Humanize Loading Screen

**Root cause:** The loading screen in `App.tsx` (lines 488-512) displays raw `initProgressCallback` log text from WebLLM. These are developer-level cache and fetch messages, not user-facing content.

**Exact changes to `src/App.tsx`:**
- Create a `getLoadingMessage(progress: number): string` function that maps progress ranges to friendly messages:
  - 0-5%: "Preparing your private journaling space..."
  - 5-30%: "Downloading AI model (this only happens once)..."
  - 30-70%: "Setting up on-device intelligence..."
  - 70-90%: "Almost ready..."
  - 90-100%: "Finishing up..."
- Replace the raw log display (`logs.slice(-4)`) with the friendly message
- Keep the percentage bar (it's useful feedback)
- Add a small note below: "First time takes a few minutes. After that, it loads instantly."
- Optionally add a subtle animated icon (the existing Loader2 spin is fine)

**Where it lives:** `src/App.tsx` (loading screen section, lines 488-512)

**Dependencies:** None

**How to test:**
1. Clear browser cache to trigger full model download
2. Verify friendly messages appear at each progress stage
3. Verify percentage still updates smoothly
4. Verify the "first time" note appears
5. On subsequent loads (cached model), verify it loads quickly with appropriate messages

**What could go wrong:**
- Progress ranges may not map cleanly to actual download stages — may need to adjust thresholds
- If WebLLM reports progress non-linearly (e.g., jumps from 0 to 50%), the messages may feel abrupt

### Priority 2: First-Time Welcome/Onboarding Hint

**Where it lives:** `src/components/ChatPanel.tsx`

**Dependencies:** None

**How to test:**

### Priority 3: CSS Transition Animations for Modals

**Root cause:** AnimatePresence was removed from MoodTracker (03-25), CrisisResources (03-26), PromptSelector (03-27), and PrivacyDashboard (03-27) due to Framer Motion v12 exit bugs. All four modals now pop in/out instantly with no animation.

**Exact changes:**
- In each of the 4 modal components, add CSS transition classes to the backdrop and content container:
  - Backdrop: `transition-opacity duration-200` with initial `opacity-0` animated to `opacity-100`
  - Content: `transition-all duration-200` with `scale-95 opacity-0` animated to `scale-100 opacity-100`
- Since these components use conditional rendering (`{isOpen && ...}` or `if (!isOpen) return null`), the enter animation works with CSS but the exit animation won't (element is removed before animation). Two approaches:
  - **Simple (enter only):** Use `animate-in` Tailwind classes — modal fades in but snaps out. Good enough for now.
  - **Full (enter + exit):** Add a `closing` state with a brief timeout before unmounting. More complex but polished.
- Recommend starting with enter-only animation (simple approach) as the improvement is significant vs. the current abrupt pop-in.

**Where it lives:** `src/components/MoodTracker.tsx`, `src/components/CrisisResources.tsx`, `src/components/PromptSelector.tsx`, `src/components/PrivacyDashboard.tsx`

**Dependencies:** Tailwind CSS 4 `animate-*` utilities or custom keyframes in `index.css`

**How to test:**
1. Open each modal — verify a brief fade-in/scale-up animation plays
2. Close each modal — verify it still closes reliably (regression test for 03-25 through 03-27 fixes)
3. Rapidly open/close — verify no animation glitches or stuck states
4. Verify CrisisResources still appears quickly (safety — don't delay crisis info)

**What could go wrong:**
- Exit animation approach (with closing state) could re-introduce the "modal stuck open" bug if the timeout isn't cleaned up properly. The enter-only approach avoids this risk entirely.
- Tailwind v4 may handle `animate-*` differently — verify utility availability

## F. UX & Design Review

### How the app feels as a product:
The reliability layer is now solid — every bug from the 03-25 through 03-27 sprint is fixed. All panels open, close, save, and persist correctly. Error handling gives clear feedback with retry. Input is never lost. This is a functional app.

But it doesn't yet feel like a *product*. The loading screen speaks developer language. The empty state gives no warmth or guidance. Modals appear and disappear like they're being toggled in a debug console. There's no moment of delight or comfort — and for a mental health app, comfort IS the product.

### What a first-time user would think:
1. "Loading... what are these technical messages? Is this safe?"
2. (After load) "Write your journal entry to start. OK... but what does this app do?"
3. (Opens mood tracker) — pops in instantly, slightly jarring
4. (Finds prompts) "Oh nice, this helps me know what to write"
5. Overall: functional but cold

### Biggest UX gap right now:
**The loading screen and empty state are the two moments where the app needs to build trust and set the tone — and both are essentially blank.** The loading screen shows technical data, and the empty state shows a single sentence. These are the "front door" moments, and they're currently unfinished.
