## A. Today's Objective

Turn QuietNote's accumulated mood + journal data into **real insight** by shipping a Mood-Journal Correlation View — the long-standing backlog feature that ties what a user writes about to how they feel — and capture structured ThoughtRecord history so the CBT mode stops throwing user work away (Objectives 2 + 1).

## B. Why This Matters

After PR #38 (continuity card, session reflections, personality settings), the app finally feels like it remembers you. The next missing piece is *interpretation*. Right now the user can see their mood history (chart) and their journal history (sessions list with reflections), but those two streams live in parallel. The app never says **"when you write about work, you tend to feel anxious"** or **"sessions about family are the ones where your mood improves the most."** That sentence is the entire promise of a journaling app with mood tracking — and we have all the data to produce it.

The ThoughtRecord gap is the other thing that nags. The CBT guide walks the user through a 5-step structured exercise — situation → automatic thought → emotions → evidence → alternative — and then discards the structure, saving only the raw chat messages. The `ThoughtRecord` type and IndexedDB shape are ready; we just never persist or surface them. A returning user gets nothing to look back on. For a CBT-style mode this is the entire point: noticing patterns in your own thoughts over time.

Time-of-day prompts is a small accent on top — morning prompts ("What do you want today to feel like?") vs evening prompts ("What's still echoing from today?") cost almost nothing and noticeably sharpen the daily-use feeling.

## G. Concrete Implementation Plan

### Priority 1: Mood-Journal Correlation View

**New utility: `src/utils/moodJournalCorrelations.ts`**

```ts
import type { Session, MoodEntry, MoodEmotion } from "../types";

export interface ThemeMoodCorrelation {
  theme: string;                  // e.g., "work"
  dominantEmotion: MoodEmotion;   // most-common emotion logged near these sessions
  emotionCount: number;           // sessions where this emotion was logged
  totalSessions: number;          // sessions on this theme
  avgIntensity: number;           // average intensity for that emotion
}

export interface MoodJournalObservation {
  kind: "theme-emotion" | "best-mood-theme" | "worst-mood-theme" | "mode-impact";
  text: string;                   // plain-English observation
  confidence: "high" | "medium" | "low"; // based on sample size
}

export function buildCorrelations(
  sessions: Session[],
  moods: MoodEntry[],
  now: number = Date.now()
): MoodJournalObservation[];
```

Algorithm:
- Restrict to the last 60 days of sessions and moods.
- For each session, extract themes via existing `extractThemes()` over concatenated user-message text.
- For each session, find moods linked by `sessionId` OR logged on the same calendar day within ±2 hours of `session.updatedAt`.
- Build a `Map<theme, MoodEntry[]>`.
- For each theme with ≥3 sessions:
  - Find the dominant emotion (mode of `emotion` field).
  - If the dominant emotion appears in ≥60 % of that theme's mood entries, emit a `theme-emotion` observation: *"You tend to feel ${emotion} when writing about ${theme} (${n} of ${total} sessions)."*
- Compute average mood intensity (normalize positive vs negative emotions; reuse existing valence mapping in `moodPatterns.ts` if present, otherwise a simple `POSITIVE_EMOTIONS = ["happy","calm","excited","content","grateful"]`).
- Emit `best-mood-theme`: theme with highest avg positive intensity.
- Emit `worst-mood-theme`: theme with lowest (only if intensity ≤ 4 to avoid false negatives).
- Optionally `mode-impact`: average mood after Gratitude / Check-in / Thought Record vs Free Write.
- Cap output to 4 observations, ordered by confidence then sample size.
- Confidence: `high` if sample ≥ 8, `medium` if 5–7, `low` if 3–4. Drop `low` if `high` or `medium` are present.

Edge cases (write tests for each):
- 0 sessions / 0 moods → `[]`.
- Sessions exist but no moods → `[]`.
- Every theme has < 3 sessions → `[]`.
- All moods same emotion → still emits, but only one `theme-emotion` per theme.
