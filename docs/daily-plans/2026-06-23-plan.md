### Priority 1 — Focus mode (`Esc`)

**State (App.tsx):**
```ts
const [focusMode, setFocusMode] = useState(false);
```

**Global key handler (App.tsx, new `useEffect`):** one document-level `keydown` listener that owns all three shortcuts (single listener, switch on key). For `Escape`:
- If **any modal is open** (`showCrisisResources || showMoodTracker || showPrivacyDashboard || showSettings`) → **return early** and let the modal's own close handler run (do not toggle focus mode). This preserves existing Esc-closes-modal behavior and avoids the PromptSelector/MoodTracker conflict.
- Else → `setFocusMode(v => !v)`.
- Guard: also return early if the active element is inside an open PromptSelector dropdown (it self-closes on Esc). Simplest robust rule: if `document.activeElement` is a `<textarea>`/`<input>` **and** the user is mid-prompt-dropdown, skip — but in practice the modal check + PromptSelector's own handler cover this. Keep it simple: modal-open check first, then toggle.

**Rendering the dim (App.tsx return, ~[App.tsx:672](../../src/App.tsx#L672) onward):**
- Wrap header, the right `SessionsPanel` column, and footer with a focus-aware class. Prefer **fade + collapse**, not unmount (so `Esc`-back is instant and animatable; matches the A2 calm aesthetic of soft 500ms transitions already on the root div at [App.tsx:673](../../src/App.tsx#L673)):
  ```tsx
  className={`… transition-all duration-500 ${focusMode ? "opacity-0 pointer-events-none -translate-y-2" : "opacity-100"}`}
  ```
  For the header, also collapse height (`focusMode ? "h-0 overflow-hidden" : ""`) or keep it `sticky` but transparent — pick whichever screenshot reads calmest; collapsing height gives the most "just the page" feel the spec asks for.
- The `right={…}` SessionsPanel wrapper ([App.tsx:840](../../src/App.tsx#L840)) already has a `hidden lg:block` pattern — add `focusMode && "lg:hidden"` so the sidebar recedes on desktop too.
- **Affordance back:** in focus mode, render a tiny, low-contrast hint (e.g. bottom-right `text-[11px] text-slate-400`) — *"Press Esc to exit focus"* — so the user is never trapped. Fade it in only in focus mode. This is the one piece of chrome that stays.
- Do **not** dim the `ChatPanel` writing surface itself, and do **not** block the crisis/disclaimer affordances inside it (safety surfaces must remain reachable — `pointer-events-none` is applied only to header/footer/sidebar, never to ChatPanel).

**Conflict to verify:** the model loading screen returns *before* the main tree ([App.tsx:631](../../src/App.tsx#L631)); focus mode never applies during loading. Good — no guard needed there.

### Priority 2 — `Cmd/Ctrl+N` → new entry

In the same global `keydown` handler:
```ts
if ((e.metaKey || e.ctrlKey) && e.key.toLowerCase() === "n") {
  e.preventDefault();
  handleNewSession();
}
```
- **Caveat to document in the PR:** `Ctrl+N` (Win/Linux) and `Cmd+N` (mac) are browser-reserved for "new window." `preventDefault()` intercepts it in most browsers when focus is in the page, but a few may still open a window — this is best-effort and acceptable for A6 (filler polish). Note it; do not over-engineer a fallback chord. If testing shows it is fully swallowed by the browser, fall back to a non-reserved alt (e.g. `Cmd/Ctrl+J`) **and update the spec note** — but try `N` first per the roadmap.
- No-op safely if already on the welcome screen (`handleNewSession` just re-clears; harmless).

### Priority 3 — `/` → prompt picker

**App side (global handler):**
```ts
if (e.key === "/" && !isTypingTarget(e.target)) {
  e.preventDefault();
  window.dispatchEvent(new CustomEvent("open-prompt-picker"));
}
```
where `isTypingTarget` returns true for `<textarea>`, `<input>`, or `[contenteditable]` (so `/` typed inside the journal textarea is a literal slash, never a hijack — **critical**, the main writing field is a textarea).

**ChatPanel side:** add a `useEffect` mirroring the crisis bridge:
```ts
useEffect(() => {
  const open = () => setPromptSelectorOpen(true);
  window.addEventListener("open-prompt-picker", open);
  return () => window.removeEventListener("open-prompt-picker", open);
}, []);
```
PromptSelector already handles the rest (`externalOpen` → opens, Esc → closes). No PromptSelector change needed.

**Edge:** `/` should be ignored when a modal is open (so it does not fight modal text fields) — the `isTypingTarget` guard covers inputs; also early-return if `showMoodTracker || showSettings || showPrivacyDashboard` to be safe.

### Implementation notes
- One consolidated `useEffect` with a single `keydown` listener keeps teardown clean and avoids three competing handlers. Put it after the handlers are defined so it closes over `handleNewSession`, `focusMode`, and the modal flags (include them in the dep array, or use a ref for `focusMode` to avoid re-binding — a ref is cleaner for a global listener).
- All new strings use plain ASCII or proper Unicode escapes (the repo has had mojibake regressions — see A1 footer fix; `…` for ellipsis, no smart quotes).
- Respect `prefers-reduced-motion`: the dim transition should still work but is fine to keep; no new motion beyond opacity/translate already used in A2.
