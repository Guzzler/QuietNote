### Next Mode: Morning/Evening Check-in (BUILD TODAY)

**How it works:**
- User selects "Check-in" mode from the mode selector
- The app detects time of day and presents an appropriate check-in:
  - **Morning (5am-12pm):** "How are you feeling this morning?" -> "What do you want to focus on today?" -> "Any worries or concerns?"
  - **Evening (12pm-5am):** "How was your day?" -> "What went well today?" -> "What would you do differently?"
- Like Gratitude mode, this is a 3-step guided flow with step indicators
- After completing all 3 steps, the AI provides a brief summary/reflection

**Model integration:**
- New system prompt for check-in mode that focuses on daily reflection facilitation
- Morning prompt: encourages intention-setting and gentle planning
- Evening prompt: encourages gratitude-in-review and self-compassion
- Same safety guardrails (medical refusal, crisis detection) apply

**UI/UX:**
- Third pill in the JournalingModeSelector: "Check-in" with a Sun/Moon icon based on time
- CheckInGuide component (similar to GratitudeGuide) shows time-appropriate prompts
- Step indicator (1/3, 2/3, 3/3) like gratitude mode
- Welcome card adapts to show morning or evening greeting

**Why this mode next:**
- Check-ins are the most natural daily journaling habit
- Time-awareness is a unique differentiator (no other journaling mode uses it)
- Reuses the same 3-step guided pattern as Gratitude, so implementation is fast
- Encourages consistent daily use — morning and evening bookends

## E. Model & Runtime Research

### Gemma 4 E2B — Updated Runtime Availability (2026-04-06)

| Runtime | Gemma 4 E2B Status | Notes |
|---------|-------------------|-------|
| **Transformers.js v4** | **YES — Working** | ONNX Q4 at `onnx-community/gemma-4-E2B-it-ONNX`. Day-one support confirmed by Hugging Face. Multimodal (text + image + audio). **Most mature browser path.** |
| **LiteRT-LM / MediaPipe** | **YES — Text-only** | Community bundle at `litert-community/gemma-4-E2B-it-litert-lm`. Web uses `.litertlm` via WebGPU. Under 1.5GB RAM with 2/4-bit quant. E4B web version has reported issues. No multimodal on web yet. |
| **@mlc-ai/web-llm** | **NOT YET** | No Gemma 4 on roadmap. Gemma 3/3n support still in progress (issues #693, #707). Project activity appears slow. |
| **ONNX Runtime Web** | **Via Transformers.js** | Native `onnxruntime-genai` doesn't support Gemma 4's PLE architecture. Transformers.js wraps ONNX Runtime Web and handles it. |
| **Chrome Built-in AI** | **NO** | LiteRT-LM powers Chrome's built-in AI (Gemini Nano), but no path for custom Gemma models. |

### Key Changes Since Yesterday's Plan

1. **Confirmed:** LiteRT-LM gets E2B under 1.5GB RAM with 2-bit/4-bit quantization — very promising for low-end devices
2. **Confirmed:** Transformers.js v4 has day-one Gemma 4 support from Hugging Face — the most reliable browser path
3. **Confirmed:** web-llm has no Gemma 4 roadmap — reinforces the need to move to an alternative runtime
4. **New finding:** LiteRT-LM web conversion is text-only for Gemma 4 (no multimodal on web yet)

### Updated Recommendation

**Primary implementation target:** Transformers.js v4 + Gemma 4 E2B ONNX Q4

**Rationale:**
- Working today with confirmed day-one support

**Deprecation path:** web-llm should remain as fallback (it's what works today) but is no longer the strategic direction. Once Transformers.js backend is proven, web-llm becomes the legacy path.
