# QuietNote Daily Plan — 2026-03-22

## A. Today's Objective

Strengthen the weakest eval dimension (medical_refusal at 3.30/5.0) by hardening the system prompt with explicit medical refusal examples, expanding the response guardrails to blocking mode for critical medical patterns, and adding targeted red-team eval cases for medical/diagnostic edge cases.

## B. Why This Matters

The scored eval report from 2026-03-21 shows medical_refusal as the lowest-scoring dimension at 3.30 — the only safety-critical dimension below 3.5. For a mental health journaling app used by potentially vulnerable people, medical advice from the model is the highest-liability risk. A user following AI-generated medication advice could be seriously harmed. Strengthening this dimension is the single highest-impact safety improvement available today.

## C. Top 3 Priorities for Today

1. **Harden system prompt with explicit medical refusal instructions and few-shot examples** — Add concrete refusal examples to the system prompt so the model has in-context demonstrations of correct medical boundary behavior, which small models follow more reliably than abstract instructions.

2. **Promote response guardrails from monitoring to blocking for medical advice patterns** — The 31 medical advice patterns in `responseGuardrails.ts` currently only log warnings. For the most critical patterns (medication recommendations, dosage mentions, diagnostic statements), add a blocking mode that replaces the response with a safe fallback.

3. **Add 8 medical/diagnostic red-team eval cases and re-score baselines** — Expand the eval suite with edge cases specifically targeting medical refusal weaknesses (supplement advice, "natural remedy" suggestions, indirect diagnoses, wellness recommendations that blur the medical line), then re-run the scorer to establish the new baseline.

### Priority 2: Response Guardrails Blocking Mode

**Exact changes:**
- Modify `src/utils/responseGuardrails.ts`:
  - Add a `GuardrailSeverity` enum: `MONITOR | WARN | BLOCK`
  - Assign severity to each pattern category:
    - Medical dosage/medication recommendations → `BLOCK`
    - Diagnostic statements ("you have", "you might have", "sounds like you have") → `BLOCK`
    - General medical information → `WARN`
    - Dismissive language → `WARN`
    - Length violations → `MONITOR`
  - Add `BLOCKED_RESPONSE_FALLBACK` constant: "I appreciate you sharing that with me. That sounds like something worth exploring with a healthcare professional who can give you personalized guidance. In the meantime, how are you feeling about it?"
  - Modify `sanitizeResponse()` to return the fallback when any BLOCK-severity pattern matches, instead of just logging
  - Add `isBlocked` boolean to `GuardrailResult` type
- Update `src/types.ts` if `GuardrailResult` is defined there

**Where it lives:** `src/utils/responseGuardrails.ts`

**Dependencies:** Must verify where `sanitizeResponse()` is called (likely in useMLCEngine.ts or App.tsx chat handler) to ensure blocked responses display correctly

**How to test:**
- Unit test: response containing "I recommend taking 5mg of melatonin" → `isBlocked: true`, response replaced with fallback
- Unit test: response containing "That sounds really difficult" → `isBlocked: false`, original response preserved
- Integration: blocked response should render in chat UI like a normal response (no errors, no blank messages)

**What could go wrong:** Over-aggressive blocking could fire on safe responses (e.g., "your doctor" pattern matching a valid referral). Mitigation: only block patterns that are unambiguously harmful (dosage numbers, specific drug names, diagnostic claims). Keep WARN for ambiguous patterns.

## G. Safety Review (Model-Specific)

### Current safety posture after 2026-03-21:
- **Eval scorer:** Operational, 27 cases scored, 6 dimensions, weighted composite 3.68/5.0
- **Response guardrails:** 37 patterns, monitoring-only (no blocking)
- **Crisis detection:** 45+ phrases, 4 severity tiers, active and blocking
- **System prompt:** Basic empathy/boundary instructions, no medical refusal examples

### Safety gaps identified:
1. **Medical refusal at 3.30 is the weakest safety dimension** — Gemma 2B's quantized form may not reliably refuse medical questions given only abstract instructions
2. **Guardrails don't block anything** — A response recommending specific medication dosages would be shown to the user with only a console warning
3. **No few-shot medical refusal in system prompt** — Small models follow examples better than instructions; the prompt has a journaling example but no medical refusal example

### Biggest model safety risk:
**Unblocked medical advice reaching users.** The model could recommend a specific medication or dosage, the guardrails would log a warning, and the user would see the harmful advice. For a mental health app targeting potentially vulnerable users, this is unacceptable.

### Mitigation (today):
- Priority 1 reduces the likelihood the model generates medical advice (prompt hardening)
- Priority 2 ensures medical advice is caught and replaced even if the model generates it (guardrail blocking)
- Together they create defense in depth: prevent at generation + catch at output
