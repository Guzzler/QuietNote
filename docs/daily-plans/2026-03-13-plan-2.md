### Priority 2: Journal Prompt Recommendation Tool

**What to change**: Create `src/utils/themeExtractor.ts` and `src/components/PromptSuggestionCard.tsx`

**Theme Extractor** (`src/utils/themeExtractor.ts`):
- Define theme categories matching existing journal prompt categories: `gratitude`, `self-reflection`, `goals`, `challenges`, `relationships`, `growth`, `creativity`
- Build keyword maps for each theme (e.g., `relationships` → ["friend", "partner", "family", "mom", "dad", "brother", "sister", "colleague", "lonely", "connection", "argument", "love"])
- `extractThemes(text: string): ThemeMatch[]` — Scan text for keyword matches, return sorted by confidence
- `getTopTheme(text: string, minConfidence?: number): ThemeMatch | null` — Convenience function
- Follow the same pure-function pattern as `emotionExtractor.ts` and `crisisDetection.ts`

**Prompt Suggestion Card** (`src/components/PromptSuggestionCard.tsx`):
- Similar to `MoodSuggestionCard.tsx` but for journaling prompts
- Shows: "Would you like to explore this further?" with a relevant prompt from the matched category
- Two actions: "Use This Prompt" (inserts prompt as user's next message or displays it prominently) and "Dismiss"
- Framer Motion animation matching existing cards
- Pulls prompts from existing `src/data/journalPrompts.ts`

**Integration in ChatPanel.tsx**:
- Run `getTopTheme()` on user messages (similar to emotion extraction)
- Guardrails (same pattern):
  - Minimum message length: 30 characters (themes need more context than emotions)
  - Cooldown: Maximum 1 prompt suggestion per 5 assistant messages (less frequent than mood suggestions)
  - Crisis suppression: Never show during crisis
  - Session dismiss limit: After 2 dismissals, stop for session
  - Never suggest simultaneously with MoodSuggestionCard (mood takes priority)
  - Deduplication: Don't suggest same category twice in a session

**Where**: `src/utils/themeExtractor.ts`, `src/components/PromptSuggestionCard.tsx`, `src/components/ChatPanel.tsx`

**Dependencies**: `src/data/journalPrompts.ts` (existing prompt database)

**How to test**:
- Unit tests for `themeExtractor.ts` (known themed sentences → correct theme)
- Manual: "I've been thinking about my relationship with my mom" → relationships prompt suggested
- Manual: Crisis keyword → no prompt suggestion
- Manual: Short message → no suggestion
- Manual: Mood suggestion already showing → no prompt suggestion

**What could go wrong**:
- Poorly timed prompts (e.g., gratitude prompt when user is expressing grief) → mitigated by not suggesting during high-negative-emotion contexts (check emotion extraction results)
- Prompts feeling forced/artificial → mitigated by warm framing, infrequent suggestions, easy dismiss
- Theme overlap with emotions → themes and emotions serve different purposes; themes guide journaling direction, emotions track mood state

## E. Tool-Calling Design Review

With the journal prompt recommendation, QuietNote will have two client-side tools following the same architecture:

| Category | Emotion Extraction (Done) | Prompt Recommendation (New) |
|----------|--------------------------|----------------------------|
| **Trigger** | Emotion keywords in user message | Theme keywords in user message |
| **Output** | MoodSuggestionCard | PromptSuggestionCard |
| **User action** | Log/Edit/Dismiss | Use Prompt/Dismiss |
| **Data write** | MoodEntry to IndexedDB | No write (just surfaces a prompt) |
| **Risk level** | Low | Very Low (read-only) |

### Pattern validation
Both tools share: client-side keyword extraction → confidence check → guardrail gates → UI suggestion card → user-confirmed action. This pattern is proving reliable and should be the template for future tools.

### Classification update
- **Safe to build now**: Journal prompt recommendation (read-only, existing data)
- **Safe to build next**: Conversation bookmarks (user-initiated metadata annotation)
- **Needs more safeguards**: Session summarization (model-dependent output quality)
- **Should not be built**: Internet access, external APIs, autonomous actions, diagnosis tools

## F. Safe Tool Ideas

### 1. Journal Prompt Recommendation (Building Today)
- **What**: Detect conversation themes, suggest a relevant journaling prompt from the curated database
- **Why safe**: Completely read-only — no data is written. Draws only from existing, human-curated prompts in `journalPrompts.ts`. User sees the prompt and decides whether to use it.
- **Permissions**: Read from `journalPrompts.ts` static data only
- **Possible misuse**: Poorly timed prompts could feel dismissive (e.g., gratitude prompt during grief)
- **Safeguards**: Crisis suppression, negative-emotion awareness (don't suggest gratitude when sadness detected), session dismiss limits, low frequency (1 per 5 messages max)

### 2. Conversation Bookmarks (Future)
- **What**: Let users mark specific exchanges as important for later review
- **Why safe**: Pure metadata — adds a flag to existing message data, no content generated
- **Permissions**: Write a boolean flag to message object in IndexedDB
- **Possible misuse**: Minimal — fully user-initiated
- **Safeguards**: Bookmarks visible in session view, deletable, no automated bookmarking

### 3. Mood Pattern Insight Card (Future)
- **What**: After a user has logged 5+ moods, show a simple trend observation ("You've logged anxious 3 times this week, mostly in work contexts")
- **Why safe**: Derived from user's own logged data, presented as observation not diagnosis
- **Permissions**: Read from IndexedDB mood store
- **Possible misuse**: Could be interpreted as diagnosis; could cause anxiety about patterns
- **Safeguards**: Frame as observation only, include "This is based on your own mood logs, not a clinical assessment", require minimum data points, user can disable

**Rejected**: Automated mood logging (bypasses user agency), emotion-based theme changes (manipulative UX), streak/gamification features (could create unhealthy obligation to journal), AI-generated affirmations without user request (could feel hollow or dismissive).
