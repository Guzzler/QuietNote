# QuietNote Daily Plan — 2026-03-13 (Day 2)

## A. Today's Objective

Implement the first client-side tool: emotion extraction from conversation text, with a mood suggestion UI card that lets users log moods directly from the chat flow.

## B. Why This Matters

- **User value**: Users often express emotions during journaling but don't manually track them. Surfacing a "Log this mood?" card after emotionally rich messages bridges the gap between conversational reflection and structured mood tracking — without requiring extra effort.
- **Safety value**: Client-side extraction (keyword/pattern matching) is deterministic, testable, and doesn't depend on model output quality. The user always has the final say (accept, modify, or dismiss).
- **Technical value**: This is the first concrete tool in the tool-calling architecture designed on 2026-03-12. Building it validates the client-side extraction + UI suggestion card pattern before investing in more complex tools.

## C. Top 3 Priorities

1. **Emotion extraction utility** — Create `src/utils/emotionExtractor.ts` with keyword/pattern-based detection of emotions expressed in conversation text. Returns detected emotion, estimated intensity, and confidence score.
2. **Mood suggestion card component** — Create `src/components/MoodSuggestionCard.tsx` that renders inline after assistant messages when emotions are detected. Shows pre-filled emotion/intensity with accept, modify, and dismiss actions.
3. **Integration + safety guardrails** — Wire the extraction + card into `ChatPanel.tsx` with proper safeguards: minimum message length, cooldown between suggestions, never suggest during crisis-detected conversations, dismiss-permanently option per session.

## D. Concrete Implementation Plan

### Priority 1: Emotion Extraction Utility

**What to change**: Create `src/utils/emotionExtractor.ts`

**Implementation**:
- Define emotion categories matching existing `MoodEntry` emotion type: `happy`, `sad`, `anxious`, `angry`, `calm`, `confused`, `hopeful`, `overwhelmed`, `grateful`, `lonely`
- Build keyword maps for each emotion (e.g., `anxious` → ["worried", "anxious", "nervous", "stressed", "tense", "on edge", "panic"])
- `extractEmotions(text: string): EmotionMatch[]` — Scan text for keyword matches, return sorted by confidence
- `estimateIntensity(text: string, emotion: string): number` — Heuristic: intensity modifiers ("very", "extremely", "a little") adjust base intensity (5) up or down
- Follow the same pattern as `crisisDetection.ts` — pure functions, no side effects, fully testable

**Where**: `src/utils/emotionExtractor.ts` + `src/utils/__tests__/emotionExtractor.test.ts`

**Dependencies**: None. Uses existing emotion types from `src/types.ts`.

**How to test**:
- Unit tests: known emotional sentences → expected extractions
- Edge cases: empty text, no emotions, multiple emotions, intensity modifiers
- False positive check: neutral sentences should return empty

**What could go wrong**:
- Over-detection (suggesting moods too often) → mitigated by confidence threshold
- Mis-labeling emotions → mitigated by user ability to modify before saving
- Missing indirect/metaphorical expressions → acceptable for v1, note as future improvement

### Priority 2: Mood Suggestion Card Component

**What to change**: Create `src/components/MoodSuggestionCard.tsx`

**Implementation**:
- Renders as a subtle card below assistant messages (not inline with message text)
- Shows: detected emotion icon, emotion name, intensity slider (pre-filled), context dropdown
- Three actions: "Log Mood" (saves via `putMood()`), "Edit & Log" (opens MoodTracker pre-filled), "Dismiss"

- Tailwind styling matching existing card patterns (soft borders, muted colors)
- Accepts props: `emotion: string`, `intensity: number`, `onAccept`, `onEdit`, `onDismiss`, `sessionId`

**Where**: `src/components/MoodSuggestionCard.tsx`

**Dependencies**: `putMood()` from `storage.ts`, `MoodEntry` type from `types.ts`, Framer Motion

**How to test**:
- Visual: render in chat flow, verify styling matches app aesthetic
- Functional: click Log Mood → verify entry appears in IndexedDB mood store
- Dismiss: click dismiss → card disappears, no data written

**What could go wrong**:
- Card could feel intrusive or surveillance-like → mitigated by subtle styling, easy dismiss, session-level disable
- Card appearing during crisis → mitigated by checking crisis detection state first

### Priority 3: Integration + Safety Guardrails

**What to change**: Modify `src/components/ChatPanel.tsx` to render `MoodSuggestionCard` after assistant messages when emotions are detected.

**Implementation**:
- After each assistant message is finalized (temp flag removed), run `extractEmotions()` on the preceding user message
- If confidence > threshold (0.6) and no active crisis detection, show suggestion card
- Guardrails:
  - **Minimum message length**: Don't extract from messages < 20 characters
  - **Cooldown**: Maximum 1 suggestion per 3 assistant messages
  - **Crisis suppression**: Never show mood suggestion when `crisisSeverity` is high/critical
  - **Session dismiss**: Track dismissed state in component state; once dismissed, don't show again in current session
  - **No nagging**: If user dismisses 3 times in a session, stop suggesting for that session

**Where**: `src/components/ChatPanel.tsx` (modifications)

**Dependencies**: emotionExtractor.ts (Priority 1), MoodSuggestionCard.tsx (Priority 2)

**How to test**:
- Manual: Type emotional messages, verify suggestion appears
- Manual: Type crisis keywords, verify suggestion does NOT appear
- Manual: Dismiss 3 times, verify suggestions stop
- Manual: Short messages ("ok", "yes") → no suggestion

**What could go wrong**:
- State management complexity in ChatPanel → keep it simple, use local useState
- Performance if extraction runs on every message → extraction is O(n) keyword scan, negligible

## F. Safe Tool Ideas

### 1. Emotion Extraction + Mood Suggestion (Building Today)
- **What**: Detect emotions in user messages, suggest logging a mood entry via inline card
- **Why safe**: Client-side keyword matching (no model dependency), user must explicitly accept, writes to existing store
- **Permissions**: Read conversation text (already visible), write to IndexedDB mood store (existing)
- **Possible misuse**: Could feel like surveillance if too aggressive; could mis-label emotions
- **Safeguards**: Confidence threshold, cooldown, crisis suppression, session dismiss, user can modify before saving

### 2. Journal Prompt Recommendation (Next Priority)
- **What**: After detecting conversation themes, suggest a relevant journaling prompt from the curated database
- **Why safe**: Read-only, draws from existing `journalPrompts.ts`
- **Permissions**: Read from static prompt data only
- **Possible misuse**: Poorly timed prompts during distress
- **Safeguards**: Never suggest during crisis, respect current emotional tone, easy dismiss

### 3. Conversation Bookmark (Future)
- **What**: Let users mark a specific exchange as important for later review
- **Why safe**: Pure metadata annotation on existing messages, no new data generated
- **Permissions**: Write bookmark flag to existing session/message in IndexedDB
- **Possible misuse**: Minimal — user-initiated only
- **Safeguards**: Bookmarks visible in UI, deletable via Privacy Dashboard

**Rejected**: Sentiment trend notifications (could cause anxiety about own patterns), automated journal entries (bypasses user agency), therapist-style interpretations (overreach for an AI tool).

### Biggest Safety Risk Today

**Mood suggestion card appearing during emotionally vulnerable moments and feeling intrusive or judgmental.** A user sharing difficult emotions could perceive "Log this mood?" as the app reducing their experience to a data point.

**Best mitigation**: Make the card visually gentle (not attention-grabbing), never appear during crisis-detected conversations, use warm language ("Would you like to remember how you're feeling?"), and make dismiss effortless (single click, no confirmation).
