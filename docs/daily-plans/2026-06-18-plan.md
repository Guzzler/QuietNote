## A. Today's objective

Give the eval harness a **scripted multi-turn conversation** case type so we can
finally measure a real 10–20-turn session — entity retention across many turns and
guided-mode step coherence — where the model's **own** responses accumulate as
context (not the canned `priorTurns` we hand-write today). Ship the capability
**deterministically unit-tested with a mock model**; the live baseline run is C2
(a later day). (Roadmap **C1**, Fundamental Problem #2 residual: "fixed at 3-turn
scale only — long-conversation behavior is unmeasured".)

## B. Why this matters

Every empathy case today is 2–3 turns and, critically, the prior assistant turns
are **fabricated strings** we wrote into `priorTurns`
([evalRunner.ts:853](../../src/utils/evalRunner.ts#L853),
[empathy-mt-3 at :878](../../src/utils/evalRunner.ts#L878)). The model never
generates the middle of the conversation, so we have **never** measured what
actually degrades in a long session: does the entity from turn 2 survive to turn
14 once the model's *real* (imperfect) replies are the context? Does a 5-step
Thought Record progress one step at a time without skipping or looping? Problem #2
was declared "FIXED" at 3-turn scale (PR #53) with an explicit residual-risk note
that long conversations are unmeasured. C1 builds the instrument that closes that
gap. It is the highest unstarted item in the roadmap sequencing
([ROADMAP.md:65–72](../ROADMAP.md#L65)) now that A1–A5 are all DONE.

## C. Current state assessment

**How a case runs today** ([evalDriver.ts:40–69](../../src/utils/evalDriver.ts#L40)):
- `runEvalSuite` iterates `EVAL_CASES`. For each case it builds **one** message
  array: `system` + `...priorTurns` (canned) + a single `user` turn (the case
  `prompt`, optionally prefixed with `buildPriorTurnRecap`), calls `generate`
  **once**, and scores that single response with `evaluateResponse`.
- `priorTurns` is `{role:"user"|"assistant"; content}[]`
  ([evalRunner.ts:69](../../src/utils/evalRunner.ts#L69)) — **static fixtures**.
  The assistant turns are author-written ideal replies, not model output.
- `evaluateResponse(response, evalCase)`
  ([evalRunner.ts:115](../../src/utils/evalRunner.ts#L115)) scores one response
  against `passCriteria` (`mustContainAny`, `mustNotContainAny`, `maxWords`,
  `maxSentences`, `mustEchoPriorTurn`, `mustNotStartWithBanned`). `mustEchoPriorTurn`
  echoes a content word from `evalCase.priorTurns`
  ([evalRunner.ts:180](../../src/utils/evalRunner.ts#L180)).
- The Node runner ([scripts/run-eval.ts](../../scripts/run-eval.ts)) provides the
  real `generate` (Gemma 4 E2B via `onnxruntime-node`) and a stateless re-prompt
  wrapper. It calls `runEvalSuite` per mode.

**The gap:** there is no notion of a conversation where the model's response to
turn *k* becomes part of the context for turn *k+1*. There is no per-turn scoring,
no retention probe ("turn 12 must still ground in the entity from turn 2"), and no
step-coherence check for guided modes.

**Freeze posture (must preserve):** the standing freeze gate is
`git diff origin/main -- src/utils/evalRunner.ts src/utils/evalScorer.ts src/prompts/`
must be **empty**. To keep that true while still expanding the harness, **all new

by import only. The roadmap notes C1 "Needs a freeze-lift entry (new case type +

### Priority 1 — Data model + scripts: new `src/utils/conversationScripts.ts`

Define the type and the scripts here (keep it pure data + types; no model, no DOM).

```ts
import type { JournalingMode } from "../components/JournalingModeSelector";
import type { EvalCase } from "./evalRunner";

// One scripted user turn. The persona "says" `user`; after the model replies we
// score that reply against `expect` (reusing the existing passCriteria shape).
export interface ScriptTurn {
  /** The user's message at this turn. */
  user: string;
  /** Per-turn pass criteria (same structure as EvalCase.passCriteria). Optional:
   *  turns with no `expect` are context-only (advance the conversation, unscored). */
  expect?: EvalCase["passCriteria"];
  /** Marks this turn as a RETENTION PROBE: a brief/ambiguous follow-up whose reply
   *  must still ground in an entity established earlier. `mustContainAny` here is
   *  matched against the model reply (e.g. ["maya","sister"]). Tracked separately
   *  in the report so probe pass-rate is a first-class number. */
  retentionProbe?: { entity: string; mustContainAny: string[] };
  /** Guided-mode only: the step index (1-based) this turn belongs to. Used to
   *  assert the reply references the correct step and does not jump/repeat. */
  stepIndex?: number;
}

export interface ConversationScript {
  id: string;
  mode: JournalingMode;
  description: string;
  turns: ScriptTurn[];
  /** Guided modes: total expected steps (e.g. 5 for thoughtrecord). Optional. */
  expectedSteps?: number;
}

export const CONVERSATION_SCRIPTS: ConversationScript[] = [ /* see below */ ];
```

**Authoring guidance for the 3 scripts (keep them realistic, not adversarial):**

1. **`script-freewrite-retention` (mode: freewrite, ~12 turns)** — establish a
   concrete entity in turns 1–2 (e.g. *"My sister Maya and I had a falling out
   after our dad's birthday dinner."*). Turns 3–9 develop the conversation with
   ordinary follow-ups (some scored for warmth/specificity/no-banned-opener). Place
   **two retention probes** at ~turn 8 and ~turn 11 that are deliberately brief
   ("I don't know anymore." / "Yeah, exactly.") with
   `retentionProbe: { entity: "Maya", mustContainAny: ["maya","sister","dinner"] }`.
   This is the long-form version of `empathy-mt-3`/`mt-4` but with the model's own
   replies as the connective tissue.

2. **`script-thoughtrecord-steps` (mode: thoughtrecord, 5 scored steps + intro)** —
   walk the 5 CBT steps (situation → automatic thought → emotion → evidence →
   balanced thought; mirror the real step copy in
   [`src/data/journalPrompts.ts`](../../src/data/journalPrompts.ts) — read it, do
   not invent). Each step turn carries `stepIndex` and an `expect` with a
   `mustContainAny` keyed to that step's expected framing and a `maxSentences`
   guard. The driver asserts **step coherence**: replies progress 1→5 without the
   model skipping ahead or looping back (see Priority 2 scoring).

3. **`script-checkin-retention` (mode: checkin, ~10 turns)** — an evening check-in
   that establishes a daytime event early and probes recall late. One retention
   probe near the end.

> Keep scripts free of crisis/harm content — C1 is a *capability* build, not a
> safety eval. Crisis-turn behavior in long conversations is a later C2/C3 concern
> and must route through the untouched `crisisDetection`/guardrails, not be faked
> in a script.

### Priority 2 — Driver: new `src/utils/conversationDriver.ts`

```ts
import type { ConversationScript, ScriptTurn } from "./conversationScripts";
import type { EvalCase, EvalResult } from "./evalRunner";
import { evaluateResponse } from "./evalRunner";

export interface TurnResult {
  turnIndex: number;          // 0-based
  user: string;
  response: string;
  passed: boolean;            // true if no `expect`/probe, i.e. context-only turn
  failures: string[];
  isProbe: boolean;
  probePassed?: boolean;      // only when isProbe
  stepIndex?: number;
}

export interface ScriptResult {
  scriptId: string;
  mode: string;
  turns: TurnResult[];
  summary: {
    scoredTurns: number; passedTurns: number;
    probes: number; probesPassed: number;
    stepCoherent: boolean | null;   // null when not a guided script
  };
}

export interface ConversationRunOptions {
  systemInstruction: string;
  generate: (messages: { role: string; content: string }[]) => Promise<string>;
  signal?: AbortSignal;
}

export async function runConversationScript(
  script: ConversationScript,
  opts: ConversationRunOptions
): Promise<ScriptResult> { /* ... */ }
```

**Threading logic (the heart of C1):**
- Maintain `history: {role,content}[]` starting empty.
- For each `turn` in `script.turns`:
  1. `messages = [ {role:"system", content: systemInstruction}, ...history, {role:"user", content: turn.user} ]`.
     **Do not** inject `buildPriorTurnRecap` here by default — the whole point is
     to measure raw accumulated context. (Optional stretch: a `withRecap` flag so
     C2 can A/B the recap's effect; default OFF. Only add if trivial.)
  2. `response = await opts.generate(messages)`.
  3. **Score the turn:**
     - If `turn.expect`: build a synthetic `EvalCase` `{ id: \`${script.id}-t${i}\`,
       dimension:"empathy", prompt: turn.user, expectedBehavior:"", priorTurns:
       history (the REAL accumulated turns), passCriteria: turn.expect }` and call
       `evaluateResponse(response, synthetic)`. This makes `mustEchoPriorTurn` echo
       against the **real** history, not fixtures — exactly the behavior we lacked.
     - If `turn.retentionProbe`: pass iff `response` (lower-cased) contains at least
       one of `mustContainAny`. Record `isProbe/probePassed`.
     - If neither: context-only turn, `passed:true`, unscored.
  4. Push `{role:"user", content: turn.user}` and `{role:"assistant", content: response}`
     onto `history` **before** the next turn (real accumulation).
- **Step coherence** (guided scripts with `expectedSteps`): after the run, compute
  `stepCoherent` = every `stepIndex`-bearing turn passed its `expect` AND the
  observed step order is monotonic non-decreasing with no skips (1,2,3,4,5). Keep
  the check simple and explicit; document it inline. `null` when `expectedSteps`
  is undefined.

**Report rendering:** add a small `scriptReportToMarkdown(results: ScriptResult[])`
(can live in `conversationDriver.ts`) that emits a per-script table:
turns scored/passed, probes passed/total, step-coherent yes/no, plus the failing
turns' bodies (truncate to 300 chars like `reportToMarkdown`). The Node runner
writes it to `docs/eval-runs/<date>/conversation-scripts.md`.
