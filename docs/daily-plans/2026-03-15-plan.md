# QuietNote Daily Plan — 2026-03-15 (Day 4)

## A. Today's Objective

Improve crisis detection to catch indirect expressions of distress and build the first mood pattern analysis utility so mood tracking delivers actionable insights — not just data collection.

## B. Why This Matters

- **User value**: Users in distress often don't use explicit keywords like "suicide" — they say things like "I don't see the point anymore" or "everyone would be better without me." Missing these means failing users when they need help most. Mood pattern analysis transforms mood logging from a passive log into something that helps users notice their own patterns.
- **Safety value**: Crisis detection is the single most safety-critical feature in QuietNote. Every missed detection is a missed opportunity to connect someone with help. This has been flagged as "Medium risk — keyword-only, can miss indirect expressions" in every prior safety review but never addressed.
- **Technical value**: Crisis detection improvements are pure logic changes with clear test cases. Mood pattern analysis reuses existing types (`MoodPattern`, `WellnessReport`) and storage infrastructure (`getMoodsByDateRange`), validating the data model designed on Day 1.

## C. Top 3 Priorities

1. **Enhanced crisis detection with indirect expressions** — Expand `crisisDetection.ts` to detect indirect suicidal ideation, passive death wishes, farewell language, and hopelessness patterns that don't use explicit keywords. Add phrase-level matching (not just single keywords) and contextual pattern detection.
2. **Mood pattern analysis utility** — Create `src/utils/moodPatterns.ts` implementing the existing `MoodPattern` and `WellnessReport` types. Analyze logged moods to surface trends (improving/declining), correlations (emotion × context), and frequency patterns (most common emotions, time-of-day clusters).
3. **Crisis detection test suite** — Create comprehensive tests for `crisisDetection.ts` covering both existing keywords and new indirect patterns. This is the first safety-critical code to get automated tests — a gap flagged since Day 1.

## D. Concrete Implementation Plan

### Priority 1: Enhanced Crisis Detection

**What to change**: Expand `src/utils/crisisDetection.ts` with indirect expression detection.

**New detection categories to add**:

*Indirect suicidal ideation* (HIGH severity):
- "don't want to be here anymore"
- "can't do this anymore"
- "there's no way out"
- "trapped with no escape"
- "everyone would be better off without me"
- "I'm a burden"
- "what's the point of going on"
- "I won't be around much longer"

*Passive death wishes* (HIGH severity):
- "wish I could disappear"
- "wish I didn't exist"
- "wish I could just sleep forever"
- "wouldn't mind if I didn't wake up"
- "don't care if I live or die"

*Farewell language* (MEDIUM severity):
- "saying goodbye"
- "want you to know I love you"
- "taking care of my things"
- "giving away my stuff"
- "writing letters to everyone"

*Escalating hopelessness patterns* (MEDIUM severity):
- "nothing ever gets better"
- "I'll never be happy"
- "there's no point"
- "why bother trying"
- "it's never going to change"
- "I'm done fighting"

**Implementation approach**:
- Add new keyword arrays: `INDIRECT_HIGH_KEYWORDS`, `PASSIVE_DEATH_WISHES`, `FAREWELL_LANGUAGE`, `ESCALATING_HOPELESSNESS`
- Extend `detectCrisis()` to check all new categories
- Maintain the same severity/action structure
- Add a `matchType` field to `CrisisDetectionResult`: `"keyword" | "indirect" | "contextual"` — so the UI can distinguish between explicit and indirect matches
- Keep backward compatibility — all existing behavior unchanged

**Where**: `src/utils/crisisDetection.ts`

**Dependencies**: None. Pure logic change.

**How to test**:
- Unit tests for every new phrase
- False positive tests: "I'm done fighting with this code" should NOT trigger (but given the mental health context, erring on the side of caution is acceptable)
- Verify existing keyword detection still works
- Verify severity levels are correctly assigned

**What could go wrong**:
- False positives from casual language (e.g., "I'm done fighting this bug"). In a mental health context, false positives are safer than false negatives. The crisis resources shown are always helpful, never harmful.
- Over-triggering could erode user trust. Mitigation: only indirect phrases trigger `show_resources`, not `immediate_help`, unless combined with explicit keywords.

### Priority 2: Mood Pattern Analysis Utility

**What to change**: Create `src/utils/moodPatterns.ts`

**Implementation**:
- `analyzeMoodTrend(moods: MoodEntry[]): "improving" | "stable" | "declining"` — Compare average intensity of negative emotions in first half vs second half of the period
- `findTopEmotions(moods: MoodEntry[], limit?: number): { emotion: MoodEmotion; count: number }[]` — Frequency count, sorted descending
- `findTopContexts(moods: MoodEntry[], limit?: number): { context: MoodContext; count: number }[]` — Frequency count from contexts arrays
- `detectCorrelations(moods: MoodEntry[]): MoodPattern[]` — Find emotion-context pairs that co-occur frequently (e.g., "anxious" + "work" appears 4 out of 5 times)
- `generateWeeklyReport(moods: MoodEntry[]): WellnessReport` — Aggregate all analysis into a WellnessReport object
- All functions are pure — accept mood arrays, return analysis. No side effects.

**Where**: `src/utils/moodPatterns.ts` + `src/utils/__tests__/moodPatterns.test.ts`

**Dependencies**: `MoodEntry`, `MoodPattern`, `WellnessReport` types from `types.ts`, `getMoodsByDateRange` from `storage.ts`

**How to test**:
- Unit tests with synthetic mood data covering:
  - Improving trend (decreasing negative intensity over time)
  - Declining trend (increasing negative intensity)
  - Stable trend (consistent)
  - Correlation detection (anxiety + work)
  - Edge cases: empty data, single entry, all same emotion

**What could go wrong**:
- Users could interpret patterns as clinical diagnosis. Mitigation: all pattern descriptions must use observational language ("You logged anxious 4 times this week") not diagnostic language ("You have an anxiety problem").
- Small sample sizes produce unreliable patterns. Mitigation: require minimum 5 mood entries before showing any patterns; require minimum 3 co-occurrences for correlations.

## F. Safe Tool Ideas

### 1. Mood Insights Card (Next Priority)
- **What**: After a user has logged 5+ moods, show a gentle insights card in the chat or mood tracker UI: "This week, you logged anxious 3 times, mostly in work contexts."
- **Why safe**: Derived entirely from the user's own logged data. Presented as observation, not diagnosis. Read-only display.
- **Permissions**: Read from IndexedDB mood store (existing)
- **Possible misuse**: Could be interpreted as diagnosis; could cause anxiety about own patterns
- **Safeguards**: Frame as observation only ("Based on your mood logs..."), require minimum 5 entries, include "This is not a clinical assessment" footer, user can disable in settings

### 2. Weekly Wellness Check-in (Future)
- **What**: At the start of a new session, if 7+ days have passed, gently ask "How has your week been?" and show a summary of logged moods for context
- **Why safe**: User-facing summary of their own data, optional and dismissible
- **Permissions**: Read mood data, display in UI
- **Possible misuse**: Could feel intrusive or like surveillance
- **Safeguards**: Only at session start, dismissible, requires existing mood data, warm framing

**Rejected**: Automated notifications/reminders (could create unhealthy obligation), mood prediction (speculative, could cause anxiety), comparison features (comparing moods across weeks could feel judgmental).

### Biggest Safety Risk Today

**Indirect expressions of suicidal ideation going undetected.** The current crisis detection relies on exact keyword matching. A user typing "I don't see the point of going on" or "everyone would be better without me" triggers zero detection. In a mental health app, this is an unacceptable gap. These are common, well-documented expressions of suicidal ideation that crisis counselors are trained to recognize.

**Best mitigation**: Add indirect expression detection with phrase-level matching, categorized by severity. Err on the side of over-detection (false positives show helpful resources; false negatives miss someone who needs help).
